ПАМЯТКА ПО ЗАПУСКУ И РАБОТЕ С ПРОЕКТОМ (DJANGO)
====================================================================

1. ЧТО ДЕЛАТЬ СРАЗУ ПОСЛЕ КЛОНИРОВАНИЯ РЕПОЗИТОРИЯ

Сначала нужно создать изолированное виртуальное окружение (venv)
и установить туда библиотеки из файла requirements.txt.
Это нужно, чтобы у всех в команде были одинаковые версии Django и пакетов,
и они не конфликтовали с другими программами на компьютере.

Шаг 1. Откройте терминал в папке проекта и создайте окружение:
  python -m venv venv

Шаг 2. Активируйте окружение (в начале строки должно появиться (venv)):
  - В Windows (CMD):        venv\Scripts\activate
  - В Windows (PowerShell): .\venv\Scripts\Activate.ps1  (или .\venv\bin\Activate.ps1)
  - В Git Bash / Mac / Linux: source venv/bin/activate

  (Если PowerShell ругается на политику безопасности, выполните один раз:
   Set-ExecutionPolicy -ExecutionPolicy RemoteSigned -Scope CurrentUser)

Шаг 3. Установите все зависимости проекта одной командой:
  pip install -r requirements.txt

--------------------------------------------------------------------

2. КАК ПОДКЛЮЧИТЬ БАЗУ ДАННЫХ

Файл самой базы (db.sqlite3) добавлен в .gitignore — у каждого из нас
она своя локальная, чтобы не ломать проект при слиянии веток в Git.
Но структура таблиц (миграции) у нас общая.

Чтобы создать таблицы у себя на компьютере, выполните:
  python manage.py migrate

После этого можно создать себе локального админа для входа в /admin:
  python manage.py createsuperuser

--------------------------------------------------------------------

3. ЗАПУСК СЕРВЕРА

Убедитесь, что (venv) активно, и запустите локальный сервер:
  python manage.py runserver

Сайт откроется по адресу: http://127.0.0.1:8000/
Остановить сервер: Ctrl + C.

--------------------------------------------------------------------

4. ПРАВИЛА КОМАНДНОЙ РАБОТЫ (ЧТОБЫ НИЧЕГО НЕ СЛОМАТЬ)

- Работаем в отдельных ветках! Не пушим напрямую в main.
  Создать свою ветку: git checkout -b имя-ветки

- Если установили новую библиотеку (например, Pillow для картинок):
  Обязательно обновите общий список зависимостей перед коммитом:
  pip freeze > requirements.txt

- Если изменили модели в файле models.py (добавили таблицу или поле):
  1. Создайте файл миграции: python manage.py makemigrations
  2. Примените её у себя:   python manage.py migrate
  3. Обязательно закоммитьте новый файл из папки migrations/ в Git!

- Когда забираете чужие изменения из Git (git pull):
  1. Проверьте, не обновился ли requirements.txt -> pip install -r requirements.txt
  2. Проверьте, не появились ли новые миграции -> python manage.py migrate
